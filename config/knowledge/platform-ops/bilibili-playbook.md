# Bilibili Operations Playbook

Owner: Neville HR. Primary users: Luna Growth, Hermione Tech, McGonagall Product.

## Positioning

Bilibili should build trust through longer explanations, real demos, and technical/product depth. It is less suitable for shallow lead magnets and more suitable for "how this system is actually built".

## Repeatable Patterns

### Build log

- Use when: a feature, workflow, or agent capability is genuinely improved.
- Do not use when: the change is only a marketing claim.
- Structure: problem, design choice, demo, limitation, next version.

### Tutorial case

- Use when: teaching a method users can copy, such as monitoring a content post or writing a compliance checklist.
- Do not use when: the content depends on private account data.
- Structure: setup, example, common mistake, template.

### Product teardown

- Use when: explaining why one-company systems need COO, Growth, Sales, Audit, and HR loops.
- Do not use when: attacking named competitors without evidence.

## Department Enablement

- Hermione provides technical accuracy and demo material.
- McGonagall converts demos into service/package insights.
- Luna adapts long videos into Xiaohongshu and Douyin fragments.
