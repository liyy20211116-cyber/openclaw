# Feishu Workflow Doc

用于把零散需求整理成飞书云文档中的正式内容。

## 适用场景

当用户提出以下需求时使用：

- 帮我整理成飞书文档
- 帮我生成 SOP / 流程说明 / 项目方案
- 帮我写会议纪要到云文档
- 帮我把工作流沉淀成可分享页面

## 推荐输出结构

默认优先整理为以下结构：

1. 标题
2. 背景 / 目标
3. 流程步骤
4. 责任人 / 角色分工
5. 风险与注意事项
6. 后续行动

## 推荐工具组合

优先使用以下工具：

1. `feishu_doc`
2. `feishu_drive`（如需归档到指定文件夹）
3. `feishu_wiki`（如需放入知识库）

## 标准动作

### 新建文档

```json
{ "action": "create", "title": "项目工作流说明", "owner_open_id": "ou_xxx" }
```

### 整体写入文档

```json
{ "action": "write", "doc_token": "doc_token", "content": "# 标题\n\n正文..." }
```

### 追加补充内容

```json
{ "action": "append", "doc_token": "doc_token", "content": "## 补充说明\n\n内容..." }
```

### 创建步骤表格

```json
{
  "action": "create_table_with_values",
  "doc_token": "doc_token",
  "row_size": 4,
  "column_size": 3,
  "values": [
    ["步骤", "负责人", "说明"],
    ["需求确认", "产品", "确认目标和边界"],
    ["执行", "研发", "按计划推进"],
    ["验收", "业务", "确认结果"]
  ]
}
```

## 工作原则

- 优先生成结构清晰、便于团队复用的内容
- 如果用户给的是零散想法，先自动整理后再写入
- 如果适合表格表达，优先补一个步骤表或责任表
- 不要把纯草稿直接原样堆进文档，先做结构化整理

## 对外回复要求

完成后至少告诉用户：

- 文档已创建 / 已更新
- 文档标题
- 文档链接或 token
- 是否补充了表格
