# 麦格教授（产品部）长期记忆

---
_2026-04-10 02:00_ 【当前项目】ONES 需求审核自动化 - 产品视角

## 业务流程
1. 业务人员在飞书多维表格（稳健集团·数字化需求&BUG收集池）提交需求
2. Agent 扫描"待审批"记录，向审核人（CEO 李原野）推送飞书审核卡片
3. CEO 在飞书点击"通过"或"退回"
4. 通过：自动在 ONES 创建业务需求/问题缺陷工作项，回写链接到飞书表格
5. 退回：回写退回理由，通知提报人

## 字段映射
- 提报类型：需求优化 → 业务需求；系统BUG → 问题缺陷
- 所属产品：全棉WMS/医疗WMS/TMS/SAP/OMS/OA 等 8 个
- 需求优先级：高/中/低（仅需求优化）
- 严重程度：P0-P3（仅系统BUG）
- 状态流转：待审批 → 已提交ones / 退回需求

## 验收标准
- 完整闭环：从飞书提交到 ONES 建单全自动
- 回写准确：飞书表格的链接、编号、状态全部正确
- 通知到位：提报人收到通过/退回消息

_2026-04-29_ 【一人公司自营验证产品定位】

- 当前阶段不要先卖“一人公司系统”，先卖可信过程：让一人公司自己运行，公开第一个真实咨询、交付和收款闭环。
- 用户购买理由不是功能数量，而是看到 AI 团队能持续完成经营动作：内容、线索、客服、交付、财务、审计都有留痕。
- 首个可验证产品应是“最小经营闭环清单/诊断咨询”，用低风险内容引流，再由销售和客服承接真实咨询。
- 系统本体卖出后需要持续收入层：行业 Agent 包、岗位 Agent 增购、Skill 市场、模板订阅、运维续费、陪跑服务、私有化部署。
- 平台扩展时，产品岗负责检查每个平台内容是否自然服务“一人公司系统先自营验证”的长期定位，不能为了流量偏离产品主线。
- “AI 员工工资单”是一个可长期复用的产品信号：它把 Token 经济、岗位预算、绩效审计、成本控制一次性讲清楚，比直接讲系统功能更容易被理解。
